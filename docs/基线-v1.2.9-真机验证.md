## 2. 真机验证结论（唯一权威一次）

- 设备：Redmi dash / Android 16 / arm64
- 产物：`简盒_signed_14_57_37_sign.apk`
- 组合：**全模块**（sigcheck + dex2c + stringenc + dex2c_stub + envcheck + packer）
- 结果：**安装、启动、运行成功**

在此之前 v1.2.3~v1.2.8 全部无法启动，失效链见第 4 节。

## 3. 产物静态核验（2026-10-27 实测）

对上述 APK 内的 `assets/xixin/{arm64,arm}/libxixin.so`：

| 检查 | arm64 | arm |
|---|---|---|
| `.bitcode` 熵 | 7.996（密文） | 7.994（密文） |
| `.text` CRC32 | `0xbbb30a8d` | `0xf38fa79d` |
| 用派生链解密后熵 | 6.563（明文） | 7.031（明文） |
| 解密后首 4 字节 | `ff4303d1` = `sub sp,sp,#0xd0` | `f0b503af` = Thumb 序言 |
| `DPT_UNKNOWN_DATA` 哨兵 | 已覆盖 | 已覆盖 |

结论：**`.bitcode` 段加密 + 证书派生链在真实产物上成立**，两 ABI 均正确。

## 4. v1.2.3~v1.2.8 失效链（供追溯，勿回退到这些版本）

| 版本 | 现象 | 根因 |
|---|---|---|
| v1.2.3~v1.2.5 | 启动 SIGABRT | `computeMaster` 里 CRC32 用 `ByteBuffer.putInt`（大端），C 侧 ARM 小端 → key 不一致 |
| v1.2.6 | 仍 SIGABRT | `init_array` 时 `/proc/self/maps` 尚无 `base.apk`；so 在 `dpt-libs/` 无 `/lib/` 可反推 |
| v1.2.7 | 仍 SIGABRT | `apk-path` 文件方案；`Log` 被 `-assumenosideeffects` 编译成 no-op，写失败静默 |
| v1.2.8 | `java_class == null` | 提供了 APK 路径，但配置解密失败：v1.2.3 误删 `DPT_UNKNOWN_DATA` 写入 |
| **v1.2.9** | **启动成功** | 恢复 `DPT_UNKNOWN_DATA` 写入 + `registerNativeMethods` fail-fast |

## 5. 已知未修复的强度缺陷（P0/P1/P2，见下节）

本基线**能跑但强度不足**，逆向检查已实证一条完整攻击链：

```
readelf -sW --dyn-syms libxixin.so | grep DPT_UNKNOWN_DATA
  → GLOBAL DEFAULT，value 0x80181
dd 定位 .data 文件偏移 0x78181，读 16 字节
  → c708fa20a3b9857069745fbaa68bd9cd   (= encKey 明文)
buildKey 从 dpt.jar MANIFEST 的 Dpt-Build-Key 取
  → aes_key = HMAC(encKey, pkg+"_"+buildKey)
  → iv      = encKey（改 iv[3]=0x2f, iv[9]=0x76）
AES-CBC 解 assets/xixin_config
  → {"jni_cls_name":"com/xixin/box/shell/JniBridge",
     "stub_seed":"139e8db5f59e0de6", "app_name":..., ...}
```

**`stub_seed` 泄漏 = 字符串加密全部可解。** 该链无需 root、无需调试器、无需脱壳。

### 待修项

- **P0**：配置 `aes_key`/`iv` 的根材料改用派生链（与 `.bitcode` 同源），
  彻底删除 `DPT_UNKNOWN_DATA` → 导出符号与明文 key 一起消失
- **P1**：移除 `.comment` 段（当前含完整 clang/LLD 版本指纹）
- **P2**：`dpt-sec-v1` / `dpt-kl-v1` / `DPT_APK_PATH` / `keyladder` 等
  敏感串不落明文

## 6. 后续改动的验收口径

任何防御改动都必须满足：

1. 本文件第 3 节的静态核验项仍全部成立（`.bitcode` 密文、两 ABI 可解、明文序言正确）
2. 真机全模块组合仍能启动运行
3. 第 5 节攻击链的对应环节失效（改哪项验哪项）
