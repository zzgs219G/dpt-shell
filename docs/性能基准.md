### 一、打包耗时（可在本机测）

测量命令：`tools/benchmark/bench-pack.sh <apk> 5`
（2026-10-07，预热 2 次；设备 = Redmi 2602BRT18C / Android 16 / Termux arm64，
工具 = CI 产物 `dpt-shell-v1.0.9.zip` vs `dpt-shell-v1.0.0.zip`；
详细数据与复测轮次见 `归档/phase1-性能优化方案.zip` 内 `phase1-test.md` §二）

| 项 | 值 |
|---|---|
| 测试 APK | `calc.apk`（MIUI 计算器，sha256 `b36efa311dec71a7…`） |
| 方法数 | 46,760 |
| 基线中位数 | **15,636 ms**（v1.0.0；样本 15419 15636 16474 16703 15353；波动 1350 ✓） |
| Task 1.7 后中位数 | **11,780 ms**（v1.0.9；样本 11995 12011 11739 11780 11589；波动 422 ✓）；归一化 251.9 vs 334.4 ms/千方法 |
| 提升幅度 | **−24.7%** |
| 通过标准 | 每方法耗时下降 ≥ 30% → **未达标**（计划书 Task 1.7 自身 ≥20% 线已达成） |

**附加对比（不参与判定）**：原作者 v2.21.0 同条件 15,298 ms——我们快 **−23.0%**；
基线 v1.0.0 比 v2.21.0 慢 2.2%（fork 起点与上游持平）。
**大包（orig-signed.apk，21 dex）**：v1.0.0 打包崩溃
（`AssertionError at Dex$Section.writeStringData`），无法对比；
v1.0.9 单方中位数 29,156 ms（波动 9092 未过门槛，仅参考）。

测量命令：`tools/benchmark/bench-runtime.sh <pkg>`
（2026-10-07，同设备同 APK 前后对照；被测 = `com.xixin.box` 简盒 v2.1.0
sha256 `b54a85d90dbe1f4b…`，原版 vs v1.0.9 默认参数加壳；
原始样本见 `归档/phase1-性能优化方案.zip` 内 `phase1-test.md` §三）

| 指标 | 基线 | 目标 | 测量设备 | 状态 |
|---|---|---|---|---|
| 冷启动 TotalTime 中位数 | 836 ms（原版 10 次） | 增量 < 150 ms | Redmi 2602BRT18C / Android 16 | ✅ 已测：加壳 1,135 ms → **+299 ms 未达标** |
| 热启动 TotalTime 中位数 | 0（Android 16 返回 0，两版皆然，不可比） | — | 同上 | ⚠ 数据无意义，记 N/A |

| 首次启动 code_cache 是否落盘 | 原版空 / 加壳空（run-as 实测） | 不落（API≥29） | 同上 | ✅ **达标** |

> **v1.1.0 复测（2026-10-11，默认磁盘加载上线后）**：同设备同方法，
